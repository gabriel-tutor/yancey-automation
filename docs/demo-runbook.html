Showing Yancey the organiser

Nine real documents in his own library are held back, unrenamed, on purpose. They are the demo. This is the order to run it in, what he sees at each step, and what to do if something goes sideways.

Before he arrives

Five minutes. Everything here is reversible, and the last item is the one that makes it so.

  • Open two tabs WF-F in n8n, and the Task Management library in SharePoint, sorted by Name. He needs to watch the second one change.
  • Check the Config node reads applyRenames: false, and the same for applyMoves, applyStructure and applyFolderRenames Four switches, four separate promises — and all four off is the resting state Act 1 depends on: the first run must change nothing.
  • Do not run it armed beforehand The nine unrenamed files are the whole demo. Spending them in rehearsal leaves you with a run that says 0 to rename, which shows nothing.
  • Rehearse with the undo If you want a dry run, do the full thing and then revert it — see Rehearsing safely at the bottom. It puts every name back.

The move

Renaming and moving are separate switches. There is exactly one move to show, and its restraint is the point.

Say the second half out loud: it will not move anything between 1. Assigned Tasks and 4. Completed Tasks, because that would be asserting how far a piece of work has got — which no file records and only he knows. A tool that moves one file and explains why it left twenty alone is more convincing than one that reorganises everything.

The questions he will ask

Short answers. Each one is true and each one is checkable in front of him.

  • “Is it reading my documents?” Yes, and that is how it can name them. Word, Excel and PowerPoint are unzipped on our own server and only the text is sent; a PDF or screenshot goes as itself because there is nothing to extract. One setting, readContents, turns it off — the naming gets worse and nothing breaks.
  • “What if it renames something a dashboard needs?” It opened all four of your Power BI reports and read what they reference. None of them reads anything in this library. That is checked, not assumed — and if a report had named a file, that file would be refused with the query quoted.
  • “Will it do this on its own?” No. There is no schedule. Somebody presses a button, and even then two separate switches decide whether anything is written.
  • “What if it gets a name wrong?” You see every name before anything happens, and what you approve is what gets applied — arming the switch does not re-ask the model. Every change keeps the old name, so any of it goes back in seconds.
  • “Can it do the rest of the site?” Yes — the library and site path are two settings in the same Config node. This library was the one to prove it on because it has the Power BI files in it, which are the hard case.

If something goes wrong

The three failures worth recognising mid-demo, and what each actually means.

  • A node goes red The run failed, which is different from finding nothing. Say so, open the Summary of the previous successful run, and carry on from the review page — the story does not depend on the live run succeeding.
  • “the model call failed, so the rules named what they could” OpenAI did not answer. The run still finishes. Press Execute again; it is usually a one-off.
  • A rename comes back failed Almost always something already sitting on that name. The call refuses rather than overwrite, which is the guarantee working. The reason is on that line in the Summary.

What not to say

Three claims that are close to true and would be wrong.

Do not say it cannot rename the wrong thing.

It can — the credential writes to that library, which is what makes it useful. What stops a surprise is that the switch rests off, the plan is read first, and the old names are kept. That is a process guarantee, not a technical one, and he will respect the difference. The mail assistant’s cannot send is a missing permission; this is not, and conflating them costs you the credibility the first one earns.

Do not say it never gets a name wrong.

It is a language model reading a document. What is guaranteed is the shape — the code assembles and validates every name, so a malformed one is not something it can produce, and a name that fails the check is dropped rather than applied.

Do not promise it will find every Power BI dependency.

It reads what is inside the file. A report published to the Power BI service, or set to refresh from a path, is referenced from outside the library, and nothing in the file or the folder shows that. Renaming the four reports was a decision, and the undo list is what covers it.
