Upperform inbox assistant & document organiser · builder reference

How the workflows actually run

Eight workflows, two data tables, a SharePoint library, and eight places a draft can die before it reaches the Drafts folder. This is the map for whoever is debugging it at 11pm.

The eight units

Only WF‑A and WF‑C hold schedules. WF‑B and WF‑D are called by WF‑A, WF‑E is invoked on failure, and the last three are hand-run: WF‑F reviews a SharePoint library and changes nothing unless it is deliberately armed, while WF‑T and WF‑S are diagnostics that never belong on a client mailbox unattended. WF‑A, WF‑B, WF‑D and WF‑E are published and running against Yancey’s live mailbox. A sub-workflow must be published before anything referencing it can be, which is why WF‑B went first.

WF‑A — the polling sequence

Sixteen nodes. The two amber rows are the idempotency gates: without both, a restart would reclassify the whole inbox and bill you for it.

1
Every Minute
Schedule trigger, pinned to America/Chicago so date maths matches Yancey’s day, not the datacenter’s.
2
Config
Every tunable in one Set node. Nothing else in the workflow should need editing.
3
Load Business Profile → Extract Profile Text
Reads /data/context/business-profile.md from the read-only mount. Both continue on error, so a broken mount degrades to a built-in fallback rather than halting the poll.
4
Resolve Context
Builds the classifier system prompt from the profile and computes the Graph $filter window. Emits profileSource — if that reads fallback, the mount is broken.
5
Fetch Inbox
GET /me/mailFolders/inbox/messages with receivedDateTime ge the lookback window. Sends Prefer: outlook.body-content-type="text" so Graph does HTML→text server-side. Retries 3× on 5xx and 429.
6
Skip Already Labelled
Gate 1. Drops anything already carrying AI-Processed, and anything from ignoreSenders — otherwise the agent triages its own digest and each one compounds into the next.
7
Skip Already Logged
Gate 2. rowNotExists on message_id. Catches the window between tagging in Outlook and the log write, where a crash would otherwise duplicate.
8
Prepare Email
Strips quoted history, trims legal footers, truncates to 6,000 chars, builds the classifier payload. A bare FYI over a deep forward chain extends past the boundary — the meaning is below the fold.
9
Classify Email
gpt-5.6-luna with a strict json_schema response format and a stable promptCacheKey. No temperature — the 5.6 family rejects it.
10
Apply Classification
Where the model’s answer gets audited. Runs the guard chain below, clamps confidence, decides the Outlook categories, computes the follow-up due date.
11
Tag in Outlook → Log Classification
PATCH /me/messages/{id} replaces the whole category array, so existing user categories are preserved and re-merged. Then one row into agent_email_log.
12
Draft This One?
The shadow-mode switch. Requires requiresDraft and draftingEnabled. Flip the second to true in Config when Yancey signs off on the labels — nothing else changes.
13
Draft Reply (WF-B)
Sub-workflow, once per message, waitForSubWorkflow on. Carries onError: continueRegularOutput — one message failing to draft must not take down the batch.

The guard chain

A message has to survive seven checks to become a draft, and an eighth to leave the mailbox. Five of the seven can overrule the model outright. Since this was drawn, an interlock has joined them: the message must also be addressed to the mailbox drafting was authorised for, so a credential re-pointed at Yancey stops drafting rather than redirecting it.

Both halves of the pricing guard changed too. It reads the whole thread for the ask, because a fee request was found sitting two replies down a quoted chain. And both halves now require proximity rather than mere co-occurrence — a money noun beside a question form to fire, a figure beside fee-stating language to stand down. Without that, an SCE capital plan quoted in a thread was releasing live fee requests, and “please send me your updates” a paragraph from the word “cost” was holding ordinary status mail.

Two of these overrule a confident model, by design.

In the live test, gpt-5.6-luna classified a client’s “can you provide an estimate of timeline and cost?” as opportunity at 0.99 confidence with requires_draft: true. pricingGuard forced it to flag_for_yancey and it never reached WF‑B. A prompt instruction would have been a suggestion; a regex over the cleaned body is a rule.

WF‑B — drafting, and the two exits

Runs once per draftable message. The blocked path matters as much as the happy one: a failed guard must leave no trace in the Drafts folder.

1
Draft Request
Twelve declared inputs from WF‑A, including the pre-encoded messageIdEnc — Graph ids are not URL-safe.
2
Create Reply Draft
POST /me/messages/{id}/createReply. Returns a real draft, correctly threaded, recipients pre-filled, original quoted. Not the n8n Outlook “reply” operation, which sends.
3
Compose Draft Prompt → Generate Draft
gpt-5.6-terra, plain text out. The profile’s voice section is in the system prompt; the classifier’s reasoning and asks go in the user turn so the reply answers the actual question.
4
Voice Guard
Three tiers. Hard — invented currency or percentage → block. Medium — invented date or large number → write it, but also tag AI-Review. Soft — missing sign-off, forbidden opener → repaired silently.
5a
Passed → Write Draft Body
Reply HTML is injected above the quoted history, not replacing it. Then re-read categories, add AI-Drafted, update the log row with the draft id and web link.
5b
Blocked → Delete the Empty Draft
The draft createReply already made is deleted, the message is tagged AI-Review, and the reason is written to guard_flags. Yancey never finds a blank reply waiting.

Closed: the orphaned draft.

If Generate Draft threw outright, the error propagated instead of routing to 5b, the cleanup never fired, and an empty draft was left in the mailbox. Seen once for real.

Routing the error output to 5b does not work — every node on that branch reads $('Voice Guard'), which never ran on the failure path, so the expressions throw and the draft is still stranded. Instead Generate Draft now continues on error and the Voice Guard absorbs the failure, returning ok: false with the draft and message ids the branch needs. It already sourced those from the trigger and the prompt node, both of which have run. No rewiring. The log records draft_failed rather than draft_blocked, so a fault does not read as a decision.

WF‑C — reconciliation without polling

The digest has to know which drafts Yancey has dealt with. It never asks him, and it never polls each draft individually.

WF‑D — reading attachments

Live since 2 September 2026. Yancey had previously been told in writing that attachments are never opened, so what changed is set out plainly rather than left to be discovered.

WF‑A calls it once per message that has attachments, and it decides per file what is worth opening. Word, PowerPoint and Excel files never leave the server. n8n’s Code node refuses require('zlib'), so the workflow carries its own DEFLATE decompressor and reads the text straight out of the archive in process. Plain text and CSV are decoded in place.

PDFs and images are the only kinds that go anywhere. They cannot be read without vision, so they are sent to OpenAI the same way the message body already is. Anything else — an executable, an archive, a file type nothing here recognises — is named and skipped rather than guessed at, and the draft acknowledges it without pretending to have read it.

Three limits keep a mailbox full of large attachments from becoming a bill: 25 MB per file, eight files per message, and at most three model calls per message. Office files and skipped files do not count against the model budget. A signature image or a logo below the reading threshold is skipped and says so, because reading a letterhead costs money and tells you nothing.

The off switch is one key. WF‑A reads attachments only when its deployment target names a wfD workflow. Clearing that key stops it everywhere at once — there is no second place to remember, and no node left half-wired.

WF‑F — the document organiser

Phase 2. It reviews a SharePoint library, categorises every document, checks each name against Yancey’s convention, and reports where each file sits. It rests switched off and changes nothing until a person arms it.

It never opens a document. Every judgement comes from what is visible on the outside: the extension, the name, and what sits beside it in the library. Reading the contents of a client’s document library would mean sending those contents somewhere, and that is a decision to take knowingly rather than one to slip into.

It proposes no moves, and that is a finding rather than a gap. A move changes a file’s path exactly as a rename changes its name, so it breaks a Power BI refresh the same way — and a .pbix keeps the paths of the files it reads inside itself, where nothing outside can see them. Moving anything between the numbered stage folders would assert how far a piece of work has got, which no file records. What it will say is when a document sits above the filing with no folder of its own.

The refusals are the interesting part. It will not rename a Power BI report, or a workbook a report probably reads, and it names the report in both cases. It will not read an eight-digit date like 04042025, because day-first and month-first disagree and being right by luck is not being right. It will not rename a file whose name already carries a version it cannot parse, or two files in one folder onto the same name, or anything without a file extension — which is how a folder can never be renamed by accident. The move uses flags=0, so it fails rather than overwrite anything already sitting on the new name.

Access took a wrong turn worth recording. An early probe used the Outlook credential against SharePoint endpoints, got 403 on everything, and concluded SharePoint was out of reach and needed a tenant administrator. It proved only that a mail credential cannot read SharePoint. The SharePoint node has its own credential type on the same Entra app, and the permissions it needs require no admin at all.

When it breaks

Symptoms seen for real during the build, and what each one actually meant.

SymptomCause
profileSource: fallbackThe mount or, more likely, N8N_RESTRICT_FILE_ACCESS_TO. Since n8n v1.123.5 it defaults to /home/node/.n8n-files, so /data/context is refused even though cat works inside the container.
Unsupported parameter: 'temperature'The 5.6 family rejects it outright. Determinism comes from the strict json_schema instead.
ErrorInvalidReferenceItem on createReplyThe target message has isDraft: true. Only ever seen with seeded fixtures — real inbound mail cannot be a draft.
550 You can only send testing emails…Historical. The digest no longer uses SMTP at all — it is written into the mailbox over Graph, so no domain needs verifying. This error can still appear from WF-E, whose failure alerts do go out over Resend to the account owner.
Digest appears in its own next digestSender missing from ignoreSenders. Compounds daily if left.
Everything classifies as flag_for_yanceyModel output unparseable, so normalizeClassification fails safe. Check guard_flags for unparseable_label.
Every error row says unknown workflow / Unknown errorThe normaliser read $input, but Config sits between the Error Trigger and it, so $input was the config object and every field fell back. Reads $('On Workflow Error') now. Two real failures were logged blank before this was found.

Ordinary mail held as a pricing requestTwo phrases far apart reading as one ask. A money noun and a question form now have to sit within 60 characters — measured against the real cases, which put genuine fee requests 19 apart and the false positives at 107 and 122.

Changing it safely

The workflows are generated from the repo, not authored in the n8n editor.

Hand-editing a Code node in n8n works until the next npm run build overwrites it. The chain is src/agent-lib.js → tree-shaken per node by esbuild → inlined into the generated SDK source → deployed. Six hundred and twenty-five tests cover it: the library itself, a parity suite proving the tree-shaken subset that ships behaves like the module under test, a vocabulary sweep that walks every term in every guard, a suite that executes the Code node bodies with stubbed $ and $input, because until then they were only ever strings that nothing ran, and a check that every generated helper is pure ASCII — which immediately found a literal non-breaking space inside a normaliser and the euro and sterling signs inside the guard that decides whether an invented fee reaches a draft. Both had survived the trip to production intact; neither would have announced itself if it had not.

Three things change without touching code at all: the business profile (edit on the VPS, picked up on the next 1-minute poll — no restart), anything in a Config node, and the Outlook categories themselves.
